## Samenvatting

Vandaag is de volledige security hardening van de Family App afgerond. De app had geen enkele beveiliging op de API routes — elke bezoeker kon gratis de Anthropic API, Google Places, Aviationstack en andere dure services aanroepen. Dat is nu dicht.

---

## Wat is gedaan

### 1. Security scan
Gevonden en gerapporteerd:
- `.env.local` en `.env` stonden al correct in `.gitignore` ✅
- `netlify.toml` bevatte geen API keys ✅
- **Probleem gevonden:** `src/index.html` bevatte hardcoded Supabase URL + publishable key

---

### 2. API authenticatie (`src/lib/api-auth.ts`)
**Nieuw bestand aangemaakt** met een centrale `requireAuth()` helper.

Toegevoegd aan **12 API routes**:
- `/api/ai-chat`
- `/api/bon-scanner`
- `/api/analyze-document`
- `/api/maandrapport`
- `/api/zoek-prijs`
- `/api/merchant-logo`
- `/api/google-places`
- `/api/weer`
- `/api/vlucht-tracker`
- `/api/wisselkoers`
- `/api/notifications/send`
- `/api/telegram/webhook`

Elke route geeft nu HTTP 401 terug als de gebruiker niet ingelogd is.

**Extra fix op `/api/notifications/send`:** `userId` werd uit de request body gehaald — iedereen kon notificaties sturen naar elke gebruiker. Nu wordt altijd de eigen user ID uit de Supabase sessie gebruikt.

**Extra fix op `/api/telegram/webhook`:** webhook signature verificatie toegevoegd via `TELEGRAM_WEBHOOK_SECRET`.

### 4. Security headers (`next.config.ts`)
Toegevoegd aan alle routes:

| Header | Waarde |
|--------|--------|
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(self)` |

### 8. Zod input validatie — alle 10 API routes
Elke route valideert nu de inkomende JSON strict met Zod. Ongeldige of kwaadaardige input wordt geblokkeerd met HTTP 400 voordat die de business logic bereikt.

Schemas per route:
| Route | Vereiste velden | Validatie |
|-------|----------------|-----------|
| `ai-chat` | `messages` | array 1–50, role enum, content max 10000 |
| `bon-scanner` | `base64` | min 1 teken |
| `analyze-document` | `base64` of `tekst` | minimaal één vereist |
| `maandrapport` | `maand`, `jaar`, financiële velden | jaar 2000–2100 |
| `zoek-prijs` | `product` | max 200 tekens |
| `merchant-logo` | `naam` | max 200 tekens |
| `google-places` | `lat`, `lng` | bereik -90/90 en -180/180 |
| `weer` | optioneel: `lat`, `lng`, `stad` | bereik gevalideerd |
| `vlucht-tracker` | `vluchtnummer` | 2–10 tekens |
| `wisselkoers` | optioneel: `van`, `naar`, `bedrag` | valutacodes exact 3 letters |

---

### 9. Rate limiting — `src/lib/rate-limit.ts`
Nieuwe sliding window rate limiter aangemaakt. Toegevoegd aan de twee duurste routes:

| Route | Limiet |
|-------|--------|
| `/api/ai-chat` | **30 verzoeken per minuut** per gebruiker |
| `/api/bon-scanner` | **5 verzoeken per minuut** per gebruiker (vision API) |

Bij overschrijding: HTTP 429 met foutmelding.
